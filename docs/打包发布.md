# 打包与发布

工具使用 PyInstaller 打包，**不支持交叉编译**：Windows 包在 Windows 上构建，macOS 包在 macOS 上构建（可用 GitHub Actions 双平台 CI）。

## 1. 依赖

```
pip install -r requirements.txt   # 含 pyinstaller
```

## 2. 一键构建

```bash
python build/build.py
```

脚本自动识别当前平台：

| 平台 | 产出 | 关键参数 |
|---|---|---|
| Windows | `dist/nanyi12306.exe` | `--onefile --windowed --icon assets/app.ico` |
| macOS | `dist/nanyi12306.app` | `--windowed --icon assets/app.icns --osx-bundle-identifier com.nanyi12306.app` |

`build/nanyi12306.spec` 为统一 spec 文件，内含平台分支。注意将 `assets/`（图标、提示音）通过 spec 的 `datas` 打进包内，代码中资源路径需用 `sys._MEIPASS` 兼容打包环境。

## 3. 平台注意事项

### Windows

- `--windowed` 隐藏控制台；调试期可去掉看日志
- 如需兼容 Win10 以下版本，在最低目标版本机器上构建

### macOS

- **Gatekeeper 拦截**：未签名 app 首次打开会提示"无法验证开发者"。两种解决：
  - 用户自助：右键 app → 打开，或终端执行
    `xattr -dr com.apple.quarantine /Applications/nanyi12306.app`
  - 正式分发：Apple 开发者证书（$99/年）签名 + notarize，自用不必
- **数据目录**：.app 包是只读的，所有运行时数据（Cookie、配置、缓存）必须写入
  `~/Library/Application Support/nanyi12306/`（代码用 platformdirs 管理）
- **证书**：依赖 `certifi`，requests 显式指定 `verify=certifi.where()`

## 4. CI 自动构建（可选）

GitHub Actions 双矩阵，打 tag 时自动产出两个平台安装包：

```yaml
# .github/workflows/release.yml（示意）
strategy:
  matrix:
    os: [windows-latest, macos-latest]
steps:
  - run: pip install -r requirements.txt
  - run: python build/build.py
  - uses: actions/upload-artifact@v4
    with:
      name: nanyi12306-${{ matrix.os }}
      path: dist/
```

macOS runner 同时承担"能否正常启动"的冒烟测试。

## 5. 发布检查清单

- [ ] 两端构建产物能启动并显示主窗口
- [ ] 扫码登录完整走通
- [ ] 查票接口正常（车站表缓存生成在正确的用户目录）
- [ ] 托盘通知与提示音正常
- [ ] 打包后资源文件（图标、提示音）加载正常
- [ ] macOS 包在 Intel / Apple Silicon 架构说明清楚（PyInstaller 产出与构建机架构一致，需 Universal2 时使用 `--target-arch universal2`）
