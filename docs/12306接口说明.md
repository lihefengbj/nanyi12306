# 12306 接口说明

本文档整理工具用到的 12306 官方接口（逆向自社区公开资料，如 py12306）。接口无官方文档且可能随时变动，协议解析逻辑统一收敛在 `core/` 层。

> 通用约定：全部 HTTPS；业务接口域名 `kyfw.12306.cn/otn`；登录域名 `passport.12306.cn`；请求头需携带 `User-Agent` 和对应页面的 `Referer`；多数响应为 `{"status": true, "httpstatus": 200, "data": ...}` 结构。

## 1. 登录（扫码）

推荐扫码登录，规避用户名密码 + 滑块验证。

### 1.1 获取二维码

```
POST https://kyfw.12306.cn/passport/web/create-qr64
body: appid=otn
```

返回：`uuid`（二维码 ID）、`image`（base64 图片，UI 直接展示）。
注意：必须为 POST 且携带 `appid=otn`，GET 请求会返回 `result_code: 9 操作失败`。

### 1.2 轮询扫码状态

```
POST https://passport.12306.cn/passport/web/checkqr
body: uuid=<uuid>&appid=otn
```

`result_code` 取值：`0`=未识别，`1`=已识别待授权，`2`=登录成功（此时返回 uamtk），`3`=已失效，`5`=系统异常。约 1s 轮询一次。

### 1.3 换取业务会话

checkqr 返回的 uamtk 在响应体中（未 Set-Cookie），需先手动种入 Cookie（域 .12306.cn）。

主流程（与官网登录页扫码成功后的行为一致）：

```
POST https://kyfw.12306.cn/otn/login/userLogin   (携带 uamtk Cookie)
```

兜底流程（官网弹窗登录路径）：

```
POST https://kyfw.12306.cn/passport/web/auth/uamtk   (appid=otn，uamtk Cookie → newapptk)
POST https://kyfw.12306.cn/otn/uamauthclient          (tk=newapptk → 业务 Cookie)
POST https://kyfw.12306.cn/otn/login/userLogin
```

完成后用 `checkUser` 校验会话。Cookie 整体持久化，启动时尝试恢复。

## 2. 车站代码

```
GET https://kyfw.12306.cn/otn/resources/js/framework/station_name.js
```

返回 JS 文本，按 `@` 和 `|` 切分，第 2 段为站名、第 3 段为三字码（如 `北京南|VNP`）。解析后本地缓存。

## 3. 余票查询

```
GET https://kyfw.12306.cn/otn/leftTicket/query
params:
  leftTicketDTO.train_date   = 2026-10-08
  leftTicketDTO.from_station = VNP
  leftTicketDTO.to_station   = SHH
  purpose_codes              = ADULT      # 学生票为 0X00
```

返回 `data.result`：字符串数组，每条以 `|` 分隔约 33 个字段。关键字段索引（以实际抓包为准，解析器需可配置）：

| 索引 | 含义 | 说明 |
|---|---|---|
| 0 | 加密串 *Str | 下单时原样提交，URL 解码后使用 |
| 2 | train_no | 内部车次号 |
| 3 | station_train_code | 车次号（G123） |
| 4/5 | 始发/终到站代码 | |
| 6/7 | 出发/到达站代码 | 用于判断始发终到 |
| 8/9 | 出发/到达时间 | HH:MM |
| 10 | 历时 | |
| 11 | 是否可售 | Y/N |
| 26 | 无座余量 | 数字/"有"/"无"/"--" |
| 28 | 硬卧 | |
| 29 | 硬座 | |
| 30 | 二等座 | |
| 31 | 一等座 | |
| 32 | 商务座/特等座 | |
| 其他 | 软卧/高级软卧/动卧等 | 按索引映射 |

`data.map`：本次查询涉及的车站代码→站名映射。

## 4. 下单链路

```
① POST /otn/login/checkUser                  # 确认登录态
② POST /otn/leftTicket/submitOrderRequest    # body: *Str, train_date, back_train_date,
                                             #      tour_flag=dc, purpose_codes, query_from_station_name,
                                             #      query_to_station_name, undefined
③ POST /otn/confirmPassenger/initDc          # 页面内嵌 REPEAT_SUBMIT_TOKEN、
                                             #      globalRepeatSubmitToken、key_check_isChange
④ POST /otn/confirmPassenger/getPassengerDTOs
⑤ POST /otn/confirmPassenger/checkOrderInfo  # body: passengerTicketStr, oldPassengerStr,
                                             #      tour_flag, randCode='', whatsSelect=1
⑥ POST /otn/confirmPassenger/confirmSingleForQueue
                                             # body: 同上 + choose_seats, seatDetailType
⑦ GET  /otn/confirmPassenger/queryOrderWaitTime?random=..&tourFlag=dc
```

关键字段：

- `passengerTicketStr`：`席别代码,0,票种,姓名,证件类型,证件号,手机号,N`，多人用 `_` 连接。席别代码：商务座 9、一等座 M、二等座 O、硬座 1、硬卧 3、软卧 4、无座 1（依配置）。
- `oldPassengerStr`：`姓名,证件类型,证件号,票种_` 每人一条。
- `queryOrderWaitTime` 返回 `data.queryOrderWaitTimeStatus`，持续轮询直到 `waitTime` 结束、`orderId` 出现（成功）或返回错误信息（失败）。

## 5. 候补下单

无票车次的合规兜底：

```
① initDc 页面解析 isHBLVote / hbInfo       # 判断该车次是否支持候补
② POST /otn/leftTicket/submitOrderRequest  # tour_flag=dc + 候补参数
③ POST /otn/confirmPassenger/confirmHB     # 提交候补队列
④ GET  /otn/confirmPassenger/queryOrderWaitTime  # 同样轮询
```

候补成功后系统按官方队列自动兑现，兑现后短信/站内信通知，用户在 App 支付。

## 6. 错误处理约定

| 现象 | 判断 | 处理 |
|---|---|---|
| 响应为 HTML 登录页 / `status=false` + 未登录文案 | Cookie 失效 | 通知 UI 切回登录页 |
| `httpstatus` 非 200 / 连接超时 | 网络/风控 | 指数退避重试，上限 30s |
| submitOrderRequest 返回 "没有可用的票" | 票被抢走 | 回到轮询循环 |
| queryOrderWaitTime 返回错误码 | 排队失败 | 回到轮询循环并记日志 |

## 7. 风控注意

- 查询间隔 ≥1.5s，带随机抖动
- 不并发请求同一接口（单任务单循环，多任务错开相位）
- 请求头模拟主流浏览器，`Referer` 与实际页面路径一致
- 单日接口调用总量应显著低于风控阈值，避免多账号轮询
